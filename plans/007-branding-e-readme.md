## Por que isso importa

O repo se declara uma vitrine pública de melhores práticas, mas a porta de
entrada é o default de outra pessoa: `<title>Create Next App</title>`,
description "Generated by create next app", home igual ao template do
create-next-app com links UTM da Vercel, metade do README ainda é o texto do
template, e `lang="en"` num produto cujo conteúdo é pt-BR. Título e description
são o que aparece em aba, busca e embed social.

### Passo 2: home própria e mínima

Reescrever `apps/web/app/page.tsx` como uma página estática simples, em pt-BR,
que apresenta o repo e aponta para a demo. Requisitos duros:

1. Manter `<Link href="/demo" data-testid="demo-link">` usando
   `next/link` — o e2e depende do testid e do prefetch.
2. Conteúdo 100% estático (sem leitura de request) — a home é origem do teste
   `instant()` e deve continuar prerenderizável por inteiro.
3. Usar tokens do design system (`bg-background`, `text-foreground`,
   `text-muted-foreground`, `font-heading`) em vez das cores hardcoded
   (`zinc-*`, `#383838`) do template — `apps/web/app/demo/page.tsx` é o
   exemplar de estilo a seguir.
4. Remover os links UTM (Templates/Learning/Deploy) e as imagens de logo que
   perderem função. Estrutura sugerida: `<main>` com `<h1>` (nome do projeto),
   um parágrafo curto (pode ecoar o tom do README), e o Link para `/demo`.

Se nenhum uso de `next/image` sobrar em `apps/web`, atualizar o bullet
`README.md:33` para dizer que o next/image fica disponível/configurado, sem
citar `page.tsx` (ou remover o bullet — escolha a frase que ficar verdadeira).
Deletar de `apps/web/public/` os SVGs que ficarem sem referência
(`grep -rn "next.svg\|vercel.svg\|file.svg\|globe.svg\|window.svg" apps/web/app`
→ os sem match podem sair).

**Verificar**: `pnpm build` → exit 0; `pnpm test:e2e` → 6/6 (em especial
